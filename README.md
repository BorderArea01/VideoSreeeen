# VideoSreeeen

多人同步观影工具，支持 **Windows、Android 和网页**，集成共同播放、画面共享、聊天室、弹幕与语音通话。

**优先共同播放**：每位成员独立加载视频，房间同步暂停、进度与倍速，保留原始画质。共享画面和本地视频实时提供继续作为可选方式。

## 开始观看

1. 打开[网页版](https://videosreeeen.pages.dev)或客户端，填写昵称并创建房间，无需注册。
2. 将自动生成的**完整邀请链接**发给朋友，对方填写昵称即可加入。
3. 播放器下方默认选中**共同播放**，粘贴视频链接开始观看；需要时手动选择共享画面或本地视频。

普通使用无需填写服务器。自建服务地址收在“设置与帮助 → 高级 · 房间服务器”；邀请链接会自动选择对应服务器。邀请包含入房凭证，请只发给预期成员，六位房间号不能单独作为完整邀请使用。

### B 站：房主装一次助手，大家都在网页看

1. 房主在电脑 Edge / Chrome [安装视频源助手](docs/browser-extension.md)，刷新放映厅。
2. 在“共同播放”粘贴 B 站视频页面，点击同步。自动复用**同一浏览器已登录的 B 站账号**；没有登录时去 B 站正常登录，回来重试，不再单独扫码授权或复制令牌。
3. 朋友打开邀请链接即可观看，**无需安装扩展、客户端或登录 B 站**。各端直接加载原站 CDN，同步播放、暂停、进度与倍速。

助手只负责取源，不读取或导出 Cookie，不把账号会话交给网页或服务器。选择正常权限下完整的 **720p / 1080p AVC 与 AAC 轨道**，可加载后才发布；失败或取消保留当前影片，不降级到游客低画质。旧的游客取源、服务端扫码实验和客户端专用登录入口均已删除。

**助手当前为 0.1.1**，修正部分视频在观众端无法加载的问题。已安装 0.1.0 的房主请从[网页入口下载更新](https://videosreeeen.pages.dev/downloads/VideoSreeeen-SourceHelper.zip)，覆盖解压目录并重新加载，然后在原房间重新同步链接；观众无需安装。[修正与实播记录](docs/verification-bilibili-html5.md)。

独立扩展已通过实际加载、真实账号与正式公网房间双端 1080p 播放；合成检查另覆盖下一分 P、取消和登录失效，见[扩展取源验证](docs/verification-browser-extension.md)。安装包尚未上架扩展商店，当前提供约 18 KB 的开源 ZIP；[一次性安装步骤](docs/browser-extension.md)。

## 选择播放方式

| 方式         | 适合什么情况                           | 视频如何到达观众                                                        | 播放控制                                           |
| ------------ | -------------------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------- |
| **共同播放** | 可播放的视频直链、已适配的原站         | 各人独立加载视频，房间只同步状态，画质不经重新编码                      | 成员均可暂停、拖动和调倍速，冲突由房间服务统一处理 |
| **共享画面** | 希望由一人提供画面，或共同播放暂不兼容 | 一位成员提供标签页、屏幕或 Windows 客户端原站的音视频，其他成员接收画面 | 在提供方的原播放器操作；观众可调本机声音和全屏     |
| **本地视频** | 想播放自己电脑或手机上的文件           | 选取文件后实时提供，无需先上传整部视频；提供者保持在线                  | 房间同步暂停、进度与倍速                           |

![播放器下方的三种播放方式与共同缓存子入口](docs/screenshots/playback-modes.png)

切换方式标签只切换输入面板，不会替换正在播放的视频；提交新视频才会切换房间媒体。

- **共享画面怎么开始？** 在电脑浏览器打开并播放原站，回到房间选择“共享画面 → 选择标签页 / 屏幕”，在浏览器选择窗口中选中该标签页并开启音频。仅点击“打开原站”不会开始共享。Windows 客户端也可共享内置原站播放器的画面。
- **共同播放怎么开始？** 粘贴可播放的 MP4 / WebM / HLS 直链，或受支持的原站页面。页面识别后先检查提供者能否加载首帧，成功才替换房间视频；失败或取消保留当前影片。
- **本地文件怎么选？** 点“本地视频 → 选择视频文件”。推荐 H.264 / AAC 的 MP4，其他编码取决于设备支持。

## 房间功能

- **三款可切换主题**：「暖夜 · 原版」「天光断层」「紫电噪讯 · C」。首次随机分配，刷新保持，手动选择后本机记忆。C 使用无照片的紫黑 / 酸绿几何界面、真实反相与细长横切片；背景点击任意按钮时短暂闪动，鼠标掠过背景不触发。装饰不重建播放器、不发房间操作，展开的弹层和全屏关闭相关动效，减少动态效果跟随系统。[主题说明](docs/appearance-signal.md)。
  天光断层采用细密的原色 / 反色切片反向错位，照片与浅色边缘交错撕裂；邀请、语音等按钮共享动效，文字、图标和视频单独保护。天光与紫电的局部悬停按每次进入约 50% 概率触发，并随机变化断层幅度与大小；紫电背景仍由按钮点击触发。相邻输入框前的碎片逐条错落收尾，避免硬边裁断。[最新交互与字体修订](docs/verification-theme-interaction.md)、[精细反色断层](docs/verification-daylight-detail.md)。
- **视频音量与网页全屏（网页版）**：播放器可单独调节本机音量、静音并记住音量；右下角“网页全屏”铺满浏览器页面，保留浏览器标签栏，支持展开聊天与语音、Esc 退出。原有系统全屏继续保留。
- **进度预览与精细定位（网页版）**：悬停查看画面与时间，按住向上拖动降低横向步长，松手同步；前后跳转可选 10 / 30 / 60 / 90 秒。播放中全屏闲置自动隐藏鼠标和控制栏。[功能边界与验证](docs/verification-player-controls.md)。
- **刷新自动恢复（网页版）**：同一标签页刷新保留房间与成员身份，主动退出后不自动重进。全屏闲置约 1 秒隐藏控件，音量、倍速和跳转预设统一放在播放设置。[恢复与底栏验证](docs/verification-refresh-toolbar.md)。
- **文字、Emoji 与图片聊天**：聊天室固定高度、内部滚动，查看历史时不被新消息强行拉到底部。右上箭头收起侧栏，右侧「聊天室」按钮展开；宽屏视频自动占用空出的空间，消息、草稿与语音状态保留。已移除拖拽悬浮，避免误触改变布局。
- **票选移出成员（新版网页）**：成员右侧「⋯」发起投票，在聊天室表决。至少 3 人在线，60 秒内获得全体在线成员严格过半同意才移出；重复投票不累加，名单变化则取消。通过后撤销该成员原房间凭据并停止其语音；无账号系统，不等同于永久封禁新身份。
- **粘贴截图**：输入框支持直接粘贴剪贴板图片，保留文字草稿。GIF / PNG / JPEG / WebP 单张最多 **20 MiB**，可查看原图；单房间图片总量限 64 MiB。
- **实时聊天弹幕**：新文字和 Emoji 可以飘过视频，支持关闭；重连不重放历史消息。图片留在聊天室，弹幕不会烧录进共享画面。
- **房间语音（试用）**：点击侧栏“加入语音”先收听，再主动开麦；最多 8 人，支持独立音量、单人静音和断线重连。“音频设备”可选择麦克风及语音输出；不能指定输出的浏览器跟随系统。优先 Opus，兼容浏览器使用带宽更高的音频编码。短时抖动独立缓冲，不暂停房间视频；严重断网仍会中断。沿用现有免费 Worker，不启用收费 TURN，不保存录音。0.4.4 安装包已包含入口，实际麦克风与输出能力需按设备验证；[语音验证](docs/verification-voice.md)、[设备选择与边界](docs/verification-voice-devices.md)。
- **人声优先**：默认开启，开麦说话或收到可听语音时，平滑把本机视频音量降至手动值的 25%，停顿后恢复。可关闭，支持语音低频过滤、清晰度均衡和动态压缩；不改变其他成员音量或房间进度。[音量与网页全屏验证](docs/verification-audio-page.md)。
- **语音短线恢复（新版网页）**：语音或房间连接短暂断开后，自动恢复本标签页已经开启且仍有效的麦克风，不再要求退出重进；手动静音保持静音。刷新页面、主动退出或设备失效仍不会自动申请麦克风。浏览器因锁屏等中断音频时，可能需要点一次「恢复声音」。[恢复、票选和缓存验收](docs/verification-room-resilience.md)。
- **成员延迟**：显示实际测得的服务器 RTT，过期显示未知。这是到房间服务的往返延迟，**不是画面延迟**。
- **下一集**：共同播放可读取原站明确提供的下一集地址，统一为房间换片；喜番为同番同线路，蜜柑为客户端原站配置，B 站为同一 BV 的下一分 P。自动续播先准备新一集首帧，短等其他在线成员，最长约 8 秒；超时后慢成员在本机加载，不暂停已开始的放映。末集或识别失败不影响当前视频。[切集首帧验证](docs/verification-next-start.md)。
- **手动共同缓存**：收在共同播放分支，默认关闭。适合可下载的视频源，不能用于实时画面。

## 原站兼容情况

以下是 **0.4.5 及截至 2026-10-27 的实际播放验证范围**，不是对站点全部线路和视频的保证。手机真机与各原站线路仍需分别验证。

| 视频来源                       | 纯浏览器共同播放                                           | Windows 客户端共同播放                       |
| ------------------------------ | ---------------------------------------------------------- | -------------------------------------------- |
| MP4 / WebM / HLS 视频直链      | 支持；需要源站允许访问、跨域和设备支持解码                 | 支持；仍受源站访问权限与编码限制             |
| 喜番／稀饭 `next.xifanacg.com` | xfy2 / AL / xfxf1 已实播验证 1080p、音频、播放控制和下一集 | xfy2 已验证；AL / xfxf1 仅验证浏览器共同播放 |
| 蜜柑 `mgnacg.com`              | 存储线路为实验识别，存在原站 403 / 520，不能保证可用       | 已实播验证原站 1080p、音频、双端同步和下一集 |
| B 站 `bilibili.com/video`      | 房主装浏览器助手取源；观众只开网页，支持同 BV 下一分 P     | 接收房间高清源；原站播放器为手动选项         |

原站仍可能因线路调整、登录、临时链接、防盗链或网络条件失效。识别到 URL 不等于能播放，具体证据见 [原站验证](docs/verification-native-sites.md)、[共同播放与聊天验证](docs/verification-chat-playback.md)、[AL 新番线路验证](docs/verification-xifan-al.md)、[xfxf1 线路与续传验证](docs/verification-xifan-xfxf1.md)。

**移动设备兼容仍需分别验证。** 已知 AL 样片采用 HEVC/H.265，电脑实播通过不代表手机也能解码。手机播放失败可使用本机重试并复制诊断；当前现场问题与验证边界见 [手机播放记录](docs/verification-mobile-source.md)。

B 站取源在房主浏览器内完成，Cloudflare 只处理房间状态；视频由各端从原 CDN 加载。扩展不共享账号凭据，不绕过登录、付费、DRM 或其他访问控制。没有正常可用高清源时保留当前影片；原站播放器和共享画面仍为手动选项。

## 使用前了解

**实时共享有缓冲与画质损耗。** 默认经独立 WebSocket 视频通道转发，不依赖远程 WebRTC 直连成功。提供者可选流畅、高清或高画质，采集目标最高 1080p / 30fps；实际效果取决于设备与网络，接收端约 2.5 秒起步缓冲。目前最多 4 位观众接收，提供者保持在线。

**公共服务有免费额度限制。** 当前使用 Cloudflare Workers Free + Durable Objects，不启用收费 TURN，也不自动升级付费。额度耗尽或网络不可达时可能无法使用；开源用户可自行部署。公共部署关闭原站视频文件代理，视频直链共同播放仍从原 CDN 加载。

<details>
<summary>共同缓存适合什么情况？有哪些限制？</summary>

当大家能取得视频源，但边播边看容易卡顿时，可以展开“共同播放 → 共同缓存”。默认关闭，提供三种开播条件：完整缓存、全员缓存首批 1/2、全员缓存首批 1/3。分批模式把首批内容写入各自磁盘并核对一致后即可开播，后台继续下载；适用于 MP4 / DASH，不提升画质，也不用于实时画面。

![共同缓存：开播条件和保存位置集中设置，说明按需展开](docs/screenshots/cache-settings.png)

面板集中显示开播条件、保存位置与启用状态；桌面并排、手机纵向排列。选择分批后会显示对应清理规则，详细限制收在“缓存说明”；展开设置或选择条件不会自动开启缓存。截图来自隔离桌面浏览器，所选目录为验收专用目录。[界面与缓存回归记录](docs/verification-cache-ui.md)。

这里按文件字节和完整下载块划批，另加 MP4 必需的初始化信息，**不是片长精确等分**。新版分批模式依据视频样本索引或 DASH 的原始 sidx 确定安全播放范围，看过一批后删除该批文件，保留解码初始化数据；下批尚未准备好时不会提前清理。进度条亮色表示全员仍保留的可跳转范围，灰色表示尚未缓存或已经清理，不能跳入；需要自由回看请选择完整缓存。缺少可靠索引时会提示改用完整缓存，不猜测清理边界。

下载速度长期低于播放所需速度或断网太久时仍可能等待，不能保证分批一定不卡顿。所有成员需使用支持分批清理的新网页 / 客户端；旧房间不会自动切换清理规则，需要全员更新后重新启用缓存。HLS 和旧 Android 客户端继续使用完整缓存。[逐批清理与灰色进度条验收](docs/verification-room-resilience.md)。

**缓存放哪：**电脑版 Chromium 网页首次缓存会让用户选择目录，建议选择 D 盘；之后保存目录句柄，可能需要浏览器再次确认权限。网站不能自行写入 `D:\`。可以通过缓存面板的“选择目录 / 更换目录”修改，文件只写入所选目录内的 `videosreeeen-disk` 子目录；不支持选目录的手机 / 浏览器仍由系统管理存储位置，并隐藏不可用的目录选择按钮。

Windows 新版源码优先使用 `D:\VideoSreeeen-cache` 下的独立应用目录，并可更换所在磁盘；没有可用 D 盘时才使用应用数据目录。用户已指定的磁盘失效时提示重新选择，不静默改回 C 盘。**已发布的 Windows / Android 0.4.6 安装包未因这次网页更新被覆盖；桌面目录设置需要包含本次改动的新客户端构建。**

| 平台              | 完整缓存范围                                                                                                                              |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Windows / Android | 完整文件、分离音视频和有限的非加密 HLS；默认最多 4 GiB，预留 256 MiB 磁盘空间                                                             |
| 浏览器            | 支持 OPFS 与独立存储线程时可分块写盘，合计最多 4 GiB，另需预留 256 MiB；不支持时仅限单轨 96 MiB、合计 128 MiB 小文件；不支持完整 HLS 缓存 |

MP4 / DASH 分块可在同房间成员间通过 WebRTC 互传，直连失败时回退源站下载；HLS 暂不支持互传，不接入公共磁力网络、DHT 或 Tracker。

全员结束后清理本应用创建的缓存，不删除用户原有文件。异常退出的原生缓存下次启动清扫；浏览器遗留缓存超过 24 小时后在后续访问清理，避免影响其他活跃标签页。

网页能播放不代表源站允许脚本下载，缓存仍需要跨域下载许可。源站未公开分块范围时，使用校验过 HTTP 状态和总长度的完整响应顺序写盘，不伪造范围；如果初始化信息在文件尾部，提前开播的收益可能很小。支持互传的文件继续使用房间 P2P。完整模式仍须下载、整文件指纹校验和全员一致性全部完成后才能播放。大文件不整段装入内存，分批实现与验收见[分批缓存与目录设置](docs/verification-cache-parts.md)。

## 本地开发

需要 **Node.js 22+、npm**。从源码启动：

```sh
npm ci
npm run build
npm start
```

打开 `http://localhost:8787`。开发时分别运行 `npm run dev` 和 `npm run dev:ui`；Windows 壳使用 `npm run desktop`，复用已构建的界面与服务。

```sh
npm run verify            # 格式、单元测试、构建、Worker 类型和 dry-run
npm run test:worker       # 本地 Workers / Durable Objects 集成验证
npm run package:windows   # Windows x64 安装版与便携版
```

维护工作站的构建与验收通过 `scripts/controlled.ps1` 串行运行，参数遵守 [AGENTS.md](AGENTS.md)。例如：

```powershell
./scripts/controlled.ps1 -File npm.cmd -Arguments @('run','build') -PrioritizeBuildWhenNoGame
```

Android 需要 JDK 17+、Android SDK 35、Gradle 8.13；先构建前端，再生成 APK：

```powershell
./scripts/build-android.ps1 -SdkRoot '你的 Android SDK 目录' -Gradle '你的 Gradle 8.13/bin/gradle.bat'
```

Windows 产物在 `artifacts/windows/`，APK 在 `artifacts/android/`。发行 APK 需要固定签名，详见 [更新与分发](docs/updates.md)；不要提交签名文件或密钥。

涉及播放器、邀请、聊天、互传或原站适配时，还需运行对应端到端验收。现有浏览器脚本使用 Windows Edge；不能以桌面视口测试代替手机真机验证。检查入口与证据见 [验证记录](docs/verification.md)。

## 自行部署

| 方案                 | 需要什么                                               | 说明                                                                                                                    |
| -------------------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| **Cloudflare**       | Workers Free、SQLite Durable Objects；可选 Pages 入口  | 无需 VPS 或独立数据库，房间状态持久化；受免费额度限制。[部署指南](docs/cloudflare.md)                                   |
| **Node.js / Docker** | 可运行 Node 的服务器及支持 WebSocket 的 HTTPS 反向代理 | 保留自建后端和视频中转。提供 [Dockerfile](Dockerfile) 与 [compose.yaml](compose.yaml)；房间状态在内存中，重启需重新建房 |

公开部署需提供 HTTPS / WSS。Node 服务默认监听 `0.0.0.0:8787`，可通过 `HOST`、`PORT`、`ALLOWED_ORIGINS` 配置；空房间 15 分钟后清理，`/healthz` 用于健康检查。当前 Node 后端不支持多节点共享房间。

自建域名需更新 `.env.production` 中的公开变量 `VITE_PUBLIC_SERVER`，并配置允许的前端来源；不要把密钥放入前端环境变量。手机访问自建服务应填写可达地址，不能填手机自己的 `localhost`。
