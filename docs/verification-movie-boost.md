# 2026-11-01 本机视频音量增强

播放设置中的音量增加百分比显示，支持的本机音轨最高 200%；用户偏好仍只保存在本机。人声优先先按当前来源能力限制手动音量，再降至其 25%，停顿后恢复到最新手动值。200% 时避让至 50%，说话期间改成 160% 则避让至 40%。静音独立于手动值与渐变状态。

## 实现边界

`client/movie-boost.ts` 从原播放器捕获本机可访问音轨，连接临时 Web Audio 增益与峰值压缩；不重新下载一遍视频、不创建第二条播放时间线、不录音或上传采样。只允许同源资源、本机缓存 / MSE Blob 或本应用已有 MediaStream，且浏览器需支持媒体元素音轨捕获。原站直连保持 100%，不修改原站签名、CORS 请求方式或权限。

主播放器不使用 `createMediaElementSource` 永久绑定。这样下一部换回不可跨域读取的原站视频时，仍使用原生声音，不会被之前的音频图静音。真正完成音轨和音频上下文就绪前，保持原生输出；增强不可用、捕获或图连接失败时恢复 100%。暂停、拖动不更换播放器；低于或回到 100%、换片、清缓存、退出时释放新增捕获轨道与上下文，不停止房间语音或共享者原来的轨道。本地文件提供者已有的 Web Audio 监听增益继续与发送轨道分开。

200% 表示数字增益设置，不等于主观响度两倍。高电平内容会被峰值压缩，不能保证所有素材都无失真。不同浏览器与设备的音轨捕获能力不一致，特别是没有 `captureStream` 的浏览器不会显示虚假的增强上限。本轮没有 Android / iOS 真机结论。

## 隔离验证

- `tests/audio-mix.test.ts`：2 项检查通过，扩充增强偏好保存、200% 边界、上限改变后先限制再避让、说话时修改手动值、恢复与静音行为。
- `npm run test:movie-boost`：独立双端房间，生成的视频及合成音源，实际完成全量缓存后从 Blob 播放。测量压缩器后的浮点波形幅度统计，150% 时 RMS 约 0.143，200% 约 0.190，比例约 1.33；静音趋近零，恢复、拖动后继续出声，其他成员保持自己的 100%。调音量和静音不发送房间播放操作。
- 同一隔离场景主动开启测试合成语音：200% 电影声音在收到语音时 RMS 约 0.048，约为之前的 25%；说话期间改成 160%，语音停顿后 RMS 恢复约 0.151。测试合成麦克风的轨道确认释放，不使用真实麦克风、不给物理设备播放测试音。
- 返回 80% 和切回远端原站型直链后，捕获轨道全部结束、相关音频上下文关闭，原播放器保持原生非静音并继续实际解码音频。主播放器的永久媒体元素 Web Audio 绑定次数为 0。
- `VS_BOOST_SCENARIO=unsupported`：在隔离浏览器中移除捕获能力，缓存视频仍有原生声音、上限 100%，不创建增强上下文。
- `VS_BOOST_SCENARIO=failure`：仅对隔离测试注入连接音频图失败，恢复原生声音、上限 100%，半成品轨道和上下文释放，无房间控制副作用。
- 原有 `test:voice` 全量回归通过：三人合成音源、Opus / 兼容编解码、180 ms 抖动、输出 / 输入设备边界、语音及房间重连、音频上下文暂停恢复、编码故障恢复、语音释放与普通视频避让。验收固定默认主题布局，并在上下文恢复后等待实际替换的编码器就绪再注入故障，避免命中已关闭实例的旧回调；没有修改语音产品实现。

测试入口均经 `scripts/controlled.ps1 -AllowGameThisRun -MinFreeMiB 0` 串行执行。实际应用没有全局测试桥接；采样监测只由隔离测试安装。原始记录位于 `.local/movie-boost-*-evidence.json`，界面截图位于 `.local/screenshots/movie-boost-settings.png`；不提交采样音频或真实用户媒体。构建、正式网页部署、资源核对与线上结果另记。
