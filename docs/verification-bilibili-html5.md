# 2026-10-28 · B 站观众加载失败与助手 0.1.1

## 现场证据

观众报告正式构建 `index-DE-TW1ln.js` 房间连接正常，原站为 `BV19rHG6EEQ6`；视频源为 `upos-sz-mirrorcoso1.bilivideo.com:443`，媒体错误码 4，networkState 3，readyState 0，实际画面为 0×0。仅凭错误码不能断言 HTTP 状态或编解码不兼容。

在用户正常登录的浏览器内，通过本项目自己的扩展读取同一视频的原站只读元数据，发现默认桌面线路还返回 `*.edge.mountaintoys.cn:4483`。增加白名单曾作为本地排查方案，但真实请求仍失败，**该域名扩展未进入最终实现**。

同一账号、同一视频的有限对照请求结果：默认桌面路线的 mountaintoys 主源与 cos 备源均返回 HTTP 403，独立无扩展浏览器不能加载；正常登录后的 `qn=80&fnval=16&platform=html5&high_quality=1` 路线向原站请求签发新地址，hwo1 CDN 返回 HTTP 206，独立浏览器实际解码 1920×1080。这里只使用原站正常返回的完整地址，没有修改现有地址的 platform、签名、域名或请求头。

仅保存主机、HTTP 状态、错误码和实际解码尺寸；签发地址只在验证进程内存中使用，没有导出 Cookie 或持久化原始响应。分线路证据为忽略目录中的 `.local/cdn-matrix-evidence.json`。

## 实现与自动检查

- 助手改为请求正常登录后的 HTML5 DASH 高清线路，仍先验证本机已登录、同 BV / cid、完整时长、非试看 / DRM、真实 AVC 720p–1080p 与 AAC。没有恢复游客 MP4 或低画质回退。
- 后台固定接口白名单同步限定上述签发参数；旧的桌面参数、附加 Cookie 参数和任意接口仍被拒绝。扩展主机权限仍只有 `api.bilibili.com`，不读取或导出 Cookie。
- 助手版本为 0.1.1。网页发起取源时拒绝旧助手，显示更新入口；观众播放既有房间媒体不调用助手。没有改动聊天室、语音、共同缓存或房间裁决。
- `npm run verify` 通过：98 项测试、格式、网页 / 服务端 / 扩展构建、Worker 类型及部署 dry-run。真实媒体播放与合成浏览器验收分别记录，不把静态通过当成观众已可播放。
- 实际隔离加载扩展的 `npm run test:extension` 通过：模拟旧助手 0.1.0 时网页在请求视频前显示更新入口，不发布媒体；恢复 0.1.1 后，无扩展观众的合成 1080p 音视频、暂停 / 跳转、下一分 P、取消与登录失效保留当前影片均通过。

## 真实房间实播与产物

更新本机自己加载的助手后，在正式公网房间使用用户给出的 `BV19rHG6EEQ6` 取源，另一个无扩展、未登录的独立浏览器加入。房主实际解码 1920×1080，独立观众实际解码 1920×1080、247 帧和 133,914 音频字节；播放、跳至 30 秒后继续出帧、暂停通过，源站返回 206。没有伪造 Referer，也没有转发账号 Cookie。播放元素重置 / 跳转时记录的 `ERR_ABORTED` 不能当成访问拒绝。证据为 `.local/extension-direct-cdn-evidence.json`。

这是同机双浏览器经公网服务及互联网 CDN 的真实检查，不代表跨运营商、手机或 Safari 现场已经通过。测试观众退出，房主测试页也主动离开并关闭；未操作用户原有房间的时间线。

助手 ZIP 为 18,483 字节，SHA-256 为 `4c94b6e9c51934513326402fd1d34a21d42da72f3a3052349113f85b38a13307`；网页主脚本为 `index-emIN2eVJ.js`，SHA-256 为 `de262e47e685b40926b6c6c5908af4c50ab4a7c4d3dc5e9c379c5e643568340f`。构建产物与上线验证分开记录，部署结果见后续记录。

## 分发边界

本次为网页和视频源助手修正，Windows / Android 版本仍为 0.4.6；不重打客户端，不覆盖 v0.4.6 原始发行资产，不创建新版本标签或触发客户端云端构建。最新版助手从网页下载，原 Release 的 0.1.0 ZIP 作为历史产物保留；Release 正文改为指向最新版网页下载。

旧房间已经保存的桌面签发地址不会因更新扩展自动替换，需要提供者在原房间重新同步同一链接；不能以普通观众“重试本机视频”冒充重新签发。手机、Safari、跨运营商和长片仍须实际验收。
