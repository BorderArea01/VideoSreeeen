# 慢成员隔离与浏览器整集缓存

2026-10-21 用户指出，网页缓存容量限制没有解决实际需求，并反馈有成员网络差时放映厅频繁回溯。本轮同时修订播放纠偏和真正的浏览器磁盘缓存，不把“返回边播边看”作为整集缓存已完成的替代。

## 播放规则

普通共同播放没有全员缓冲屏障。网页的 waiting / stalled 不发送房间控制命令，服务端不会根据某个成员缓冲暂停所有人。旧的本机纠偏仍可能制造卡顿：漂移超过阈值便硬跳，包括向后回退和跳入未缓冲的未来位置。新代码限制自动纠偏为缓冲范围内的向前追赶，走得过快时减速；显式手动拖动、暂停对齐和首次加入保留。原生原站桥接遵守相同限制。

同房间旧版本快照不覆盖新版本；聊天和 RTT 不重设播放时钟。播放进度条显示本机实际进度，缓冲和落后状态明确标注，不伪装已经同步；RTT 列表仍显示同一份真实服务器挑战样本。一个慢成员的手动拖动仍是全房间操作，符合多人可控的既有规则。

## 浏览器磁盘缓存

- 小文件保留已验证的 Cache Storage 路径。超过单轨 96 MiB 或合计 128 MiB 时，支持 OPFS / Web Locks / 独立存储线程的浏览器改用磁盘路径；上限为合计 4 GiB，检查配额并预留 256 MiB。缺少能力的浏览器保持原有小文件限制。
- 使用应用独立目录，每次下载独立代次；以 256 KiB 写入、读取和校验，独立线程在完整写入后顺序计算 SHA-256，再将磁盘 File 交给播放器。没有整文件 Uint8Array、整文件 arrayBuffer 或将所有分块聚合为内存 Blob。
- CDN 不向脚本公开 Content-Range 时，HEAD 取得总大小，再请求完整 HTTP 200 响应；验证总长度，逐块写盘，短响应、超长、超时及取消均不能就绪。没有改签发 URL、绕过 CORS、增加视频代理或付费服务。
- 保留 P2P 分块校验、背压和源站回退；整集写盘的种子继续从磁盘向同房成员提供分块。全员完整并且指纹一致才放行；换片、退出、失败和结束只清理本应用的目录。
- 24 小时遗留目录清扫先尝试 Web Lock，其他活跃标签页持锁时跳过。缓存读盘／解码失败会撤回本机 ready，重试先释放旧播放器与文件，不让损坏缓存保持全员就绪。

参考 [MDN OPFS](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system)、[File System 标准](https://fs.spec.whatwg.org/) 与 [noble-hashes](https://github.com/paulmillr/noble-hashes)。新增运行时依赖 @noble/hashes 精确固定为 2.4.0、MIT；这是原依赖树已有版本，现用于独立线程流式 SHA-256。

全员就绪后，在测试浏览器中阻断该 CDN 请求，两端仍从磁盘 File 对应的 blob URL 播放，均实际解码 1920×1080，并拖到第 60 秒后继续播放。截图核对手机视口的缓存完成状态与控件，长视频没有触发旧的 96/128 MiB 限制。摘要为 `.local/cache-disk-al-local-evidence.json`。

### 三端限速

`test:playback-buffering` 使用真实 Sintel MP4 与三个独立浏览器资料，仅对一位观众的视频响应暂停传输 8 秒，再分阶段恢复；房间 WebSocket 与其他成员不注入故障。慢成员触发实际 waiting / stalled，并显示“本机缓冲中”。

- 正常两端分别播放到 13.564125 / 13.548667 秒、各 330 帧，观察期间无 waiting、自动 seek 或回退。
- 慢成员恢复后到 13.535429 秒，与第一端相差约 0.029 秒；只发生一次向前追赶，没有向后跳转，没有向房间发送暂停、换片或 seek。
- 慢成员主动拖回第 4 秒后，三端仍即时共同跟随，保留多人可控。
- 这验证了注入故障下的隔离与恢复，不能据此声称已还原用户原网络中所有回溯原因。原代码允许自动回退和跳入未缓冲位置，单元及桥接测试对这些规则分别约束。

摘要为 `.local/playback-buffering-local-evidence.json`。Windows 原生桥接回归通过播放／暂停、拖动、1.5 倍速、原站独立弹幕和下一集读取超时；使用独立测试资料目录，没有读取用户本机登录态。测试启动改为显式传入资料目录，并在首个窗口就绪后核对，避免早期主进程评估发生 Promise 被回收的工具错误。

原有 P2P 回归通过浏览器互传、协作下载、损坏块拒绝与源站回退、Windows / 浏览器双向传块、种子离开和缓存清理。旧的小文件路径及原生磁盘缓存保持可用。

4 秒心跳排队与同版本聊天的校时回归也通过：两端各 626 帧、25.892812 / 25.910707 秒，没有自动 seek 或显示进度跳变，手动拖动仍即时跟随。

没有操作任何 Android 设备或用户原房间，也不以 Windows 浏览器的手机视口模拟冒充手机真机。当前记录不代表新安装包已发布。
