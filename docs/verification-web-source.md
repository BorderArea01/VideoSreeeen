# 网页原站播放入口修订

2026-10-18，基于 0.4.0 修订网页版的原站播放流程。

## 原因与行为

旧提示“等待客户端识别视频”并不代表浏览器正在解析视频。仅有原站页面地址、没有成员提供视频源或共享画面时，浏览器不会读取其他网站的播放器，原提示会一直保留，造成正在加载的错觉。

现在立即显示“选择播放方式”，提供“打开原站”“共享视频标签页”“打开视频文件”。支持屏幕共享的电脑浏览器可以直接提供原站标签页，其他成员接收音视频；不支持屏幕共享的浏览器隐藏该按钮，仍显示文件和邀请入口。客户端识别、原站画面共享、视频直链与共同缓存继续保留。

标签页选择器必须由用户点击触发，不能自动授权。采集优先提示浏览器标签页、排除当前房间标签页，避免递归共享。取消或拒绝后可重试，未开始的共享不替换房间媒体；房间或视频改变后，旧选择结果不能发布到新媒体。屏幕共享的进度在提供方原站操作，接收端不提供拖动和倍速控制。

参考：[屏幕采集 API 与用户手势要求](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia)、[VideoTogether 安装方式](https://videotogether.github.io/en-us/guide/install.html)。保留原站登录和画质权限，不读取、分发登录 Cookie。

## 本机验证

- `npm run verify`：格式检查、24 项测试、TypeScript、前端与 Node 构建、Workers 类型检查和 dry-run 通过。
- `test:onboarding`：原站链接立即提供可用操作，邀请、重连、聊天和移动布局通过。
- `test:browser-share`：使用真正的浏览器标签页采集 API，自动选择仅属于测试的独立标签页，不采集用户桌面或其他应用。接收端解码视频并接收音轨；本地示例首次接收 1590×1062、11 帧，音频采样 27,840；取消后重试、停止清理及无屏幕共享能力的备选入口通过。
- 同一测试使用此前用户提供的 B 站 `BV13Aa66LEAW`：原站视频播放后，网页成员收到整个标签页的真实画面与音轨；本次接收 1590×1062、11 帧，音频采样 35,040。采集尺寸不等于原站高清权限。本机测试静音，未做扬声器听感验收。
- `test:broadcast`：从上述备选入口实际选择本地文件并经 WebRTC 传送，接收 960×540、音视频轨；播放、暂停、拖动、后来加入和停止清理通过。共同缓存未自动开启。
- `test:ui`：2,097,194 字节 GIF 原图查看、双端真实播放、完整缓存内容一致、自然播放结束后的缓存清理、Windows 真实磁盘缓存与清理通过。B 站、喜番、蜜柑的本轮原站探测均找到播放器和视频源；后两个站点仅为探测，不能称为整片播放已验收。
- `test:p2p`：浏览器互传、Windows 与浏览器双向互传、共同下载避免重复取源、损坏分块校验与源站回退、提供者离开后播放及缓存清理通过。

结构化证据与截图在本机忽略目录 `.local/`。测试均串行经过资源守卫，未安装或操作 Android 设备。Safari/iOS、Android 真机、跨网络 P2P 与长时间播放尚未在本轮验证。0.4.0 已发布安装包的基线记录仍见 [verification.md](verification.md)。
