# 共同播放优先与 B 站游客画质

## 2026-10-25 用户链接的网页版复验

链接 `https://www.bilibili.com/video/BV1TuHM6REHk/` 在全新隔离 Edge、显式 Clash 代理、未登录状态下，官方网页 HTTP 200，正常播放接口 code 0 / quality 32，实际解码 640×360 / 5 帧，时长 1773 秒。接口还返回 852×480 的匿名轨道；菜单列出 1080p 不等于返回了该轨道。本轮没有导入账户 Cookie 或修改播放权限。

同一浏览器、同一代理中，将官方正常响应所给的匿名视频 / 音频地址仅在内存中交给正式网页入口进行实际加载：两个媒体元素均 readyState 0、错误码 4，网络报告 `ERR_BLOCKED_BY_ORB`。从网页匿名读取 B 站 view 接口，报告 CORS 与 `ERR_FAILED`。未获得可确认的媒体 HTTP 响应状态，不能把本轮失败擅自写成 HTTP 403。脱敏证据 `.local/bili-user-link-web-evidence.json`，没有保存临时地址、原始响应、Cookie 或底层完整错误消息。

官方外链播放器实际加载 640×360；本轮检查 window 的 message 事件监听器为空，未验证出能供外站可靠双向同步暂停 / 拖动的控制接口。[官方外链说明](https://player.bilibili.com/) 提供嵌入与初始时间等参数；能够显示原站画面不能作为共同控制通过的证据。脱敏结果 `.local/bili-current-embed-capabilities.json`；正常匿名画质证据 `.local/bilibili-quality-desktop-evidence.json`。

结论：此链接本身正常，当前网页版 B 站共同播放仍未实现；提示来自本应用已有的能力边界判断。本轮仅完成复验，未取消边界判断、伪造同步或将尚不可用的源发布给房间，也未部署或发布新功能。现有可用路径仍为各自使用客户端内的原站播放器，或手动共享画面。视频代理关闭、无需扩展、零付费、原站权限和本机登录会话边界保持。

## 产品方向与实现

2026-10-20 用户要求共同播放为重点，一人提供视频源或画面保留但不主推。

- 播放方式首项与默认输入面板改为共同播放，键盘导航顺序保持与界面一致。
- 共享画面、本地文件实时提供和独立 WebSocket 视频转发保留，必须由用户手动选择；选择面板不发布新媒体或中断当前视频。
- 第一次使用帮助先说明各自加载视频和同步控制。网页提交 B 站页面时说明共同播放需要客户端，保留当前视频；共享画面仍可手动选择。
- 浏览器收到尚无视频源的原站共同播放时，说明本端兼容边界，不以等待某成员共享画面暗示稍后一定能共同播放。显式打开提供画面窗口仍显示对应操作。
- 房间权威状态、冲突处理、缓存门槛、原站权限、本机登录会话和视频转发协议没有改动。

## B 站正常匿名路径复验

脚本：`npm run test:bilibili-quality -- <B站视频页面>`。使用新的独立浏览器存储，观察官方页面正常发出的播放请求和实际视频解码，只保存脱敏摘要，不保存 Cookie、临时 CDN URL 或原始响应。`VS_PROXY_URL` 可显式选择测试代理，不修改系统网络。

| 视频           | 正常播放接口实际返回               | 菜单列出的高清档位            | 实际解码            |
| -------------- | ---------------------------------- | ----------------------------- | ------------------- |
| `BV13Aa66LEAW` | 852×480、640×360，AVC / HEVC / AV1 | 1080p60、1080p、720p          | 640×360，164 秒视频 |
| `BV1KQp565ENm` | 640×480、480×360，AVC / HEVC / AV1 | 4K、1080p 高码率、1080p、720p | 480×360，196 秒视频 |

两个页面均 HTTP 200，官方 `/x/player/wbi/playurl` 均为 HTTP 200 / code 0 / quality 32，无 SESSDATA 登录会话。菜单或 `support_formats` 声明存在 1080p，不代表匿名响应包含对应视频流。本轮未取得游客 1080p 源，不宣称已实现游客 1080p 或所有 B 站视频的统一匿名画质能力。

同一 `BV13Aa66LEAW` 的官方手机网页（Pixel 7 浏览器视口）实际解码 640×360 / 4 帧；官方外链播放器 `player.bilibili.com` 正常参数路径同样解码 640×360 / 4 帧，播放接口仍仅返回 360p / 480p。它们不是 Android 真机或用户登录后高清的验收。

这不影响既有 Windows 原站共同播放：每位成员仍独立使用自己的原站播放器和权限。此前游客 360p 双 Windows 与正式房间服务同步已通过，见 [原站验证](verification-native-sites.md)、[0.4.3 验证](verification-chat-playback.md)。

研究参考：[Bili-SyncPlay](https://github.com/sky1wu/Bili-SyncPlay)、[VideoTogether](https://github.com/VideoTogether/VideoTogether) 的原站播放同步方式，以及 [yt-dlp 当前 B 站提取器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/bilibili.py) 对实际返回格式和缺少格式的区分。没有整体导入参考项目代码或替换原站权限检查。

## 共同播放内的本机登录入口（未发布）

用户询问能否弹窗授权、快速复用系统浏览器已经登录的 B 站令牌。调查官方开放平台 OAuth 后，没有找到能将系统浏览器的观看会话直接授权给第三方播放器的公开接入路径；开放接口 access token 不能直接当作原站播放器 Cookie。

客户端 B 站共同播放来源栏增加“登录 B 站”，复用既有官方登录窗口和独立本机原站会话。窗口关闭后刷新当前 B 站播放器，仍可在官方页面扫码或按正常流程登录。没有增加系统浏览器 Cookie 导入或服务端账号托管。

`npm run build` 与 `npm run test:site-account` 通过。使用全新隔离测试资料，仅以 `.invalid` 域合成 Cookie 检查原站会话持久化与房间会话隔离；官方登录页实际加载，共同播放栏按钮能直接打开登录窗口，原站窗口没有应用桥接，关闭后房间窗口保留。未使用真实账号，不能将此结果称为登录后高清通过。未部署或发布客户端。

依据：[B 站官方开放平台 OAuth 示例](https://github.com/bilibili-openplatform/demo/blob/main/java/Demo.java)、[官方授权权限列表](https://open.bilibili.com/doc/4/08f935c5-29f1-e646-85a3-0b11c2830558)、[Electron 独立会话](https://www.electronjs.org/docs/latest/api/session)。

## 系统浏览器扫码确认实验：失败，已撤回入口

2026-10-20 尝试将客户端生成的官方扫码登录请求交给系统浏览器确认。生成接口和轮询可以工作，用户浏览器也显示了已登录账号，但用户反馈“确认”按钮禁用，实际未完成登录；请求最终过期，测试进程已退出。

重新检查官方页面代码：`scan-web` 组件初始 `disabled: true`，挂载时若不在 B 站 App 环境则直接返回，跳过扫码状态初始化；其公共模块的 App 判断为 `BiliApp|BiliComic|hikari|MissEvan`。因此，普通浏览器显示账号不能作为支持此种授权的证据。此前将生成与等待成功推断成浏览器可完成确认是错误的；模拟轮询测试也不能证明真实授权成功。

已移除未发布的浏览器确认实现、轮询和“浏览器授权登录”按钮，恢复共同播放来源栏直接打开官方客户端内登录窗口；不伪装 App、不启用灰色按钮、不调用确认接口绕过页面限制。可以在官方登录窗口使用 B 站 App 扫码或原站提供的其他登录方式，登录会话只在本客户端保存。系统浏览器现有会话的直接授权、本次真实账号登录与登录后高清均未验收，未打包、发布或部署。

撤回后重新执行 `npm run build`、`npm run test:site-account`，均通过。实际截图可见官方二维码、密码和短信登录入口；设置与共同播放来源栏均可打开同一独立会话窗口，重复点击复用窗口，关闭后房间窗口保留。只使用隔离测试资料和合成 Cookie 验证会话持久化，未完成真实账号认证。

核查的官方静态代码：[扫码页组件](https://s1.hdslb.com/bfs/static/2233-monorepo/account-h5/static/js/async/5717.d890ef29.js)、[公共 App 环境模块](https://s1.hdslb.com/bfs/static/2233-monorepo/account-h5/static/js/6768.aabdf5fe.js)。仅保留此结论与公开资源地址，原始文件留在忽略目录；不记录用户账号、二维码请求或会话。
