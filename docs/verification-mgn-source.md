# 蜜柑页面共同播放

2026-10-19。用户截图中的 `https://www.mgnacg.com/bangumi/193-3-17/` 在原站可以播放，却被共同播放入口一概判定为不能处理。此前仅用公开直链和受控原站样片验收，不能代表这个实际使用路径已通过。

## 调查与修改

- 原站公开页面与播放器实际加载成功，正常播放器从原 CDN 获得带期限的视频地址。该路径包含站点公开的逐响应 URL 编码信息，不是需要复制用户 Cookie、登录或绕过付费、DRM 的路径；原站签发的完整地址及其期限保持不变。
- 为蜜柑存储线路增加页面元数据识别。仅允许特定原站播放页、站点配置和实际解析器路径，视频源只接受当前已验证 CDN。服务端解析 JSON 和公开响应值，不执行远程脚本、不生成或篡改源站访问凭据。
- 新接口 `/resolve-source/<room>` 要求在线成员身份，前后验证成员，限制请求大小、响应大小、并发和重试频率，整体识别超时 12 秒。选择另一面板、修改地址、换片、离开及识别失败不应发布旧结果。当前影片在识别期间继续保留。
- Cloudflare 只读取少量页面元数据。视频仍由每位浏览器直接从原 CDN 加载，不启用 `/media` 原站视频代理、不重编码、不调用付费浏览器或付费 TURN。Node 自建服务保留现有 HTTP 媒体代理；适配器的非标准端口仅用于固定元数据解析器，没有扩大原媒体代理的默认端口范围。
- 当前支持此链接对应的“存储线路”，没有宣称所有蜜柑线路、其他视频网站或客户端真机均通过。未适配线路给出明确说明和可选共享入口。

## 验证

- `npm run verify` 通过：43 项测试、类型、构建、Worker 类型与 dry-run。新增检查包含元数据解码、原始临时地址保留、脚本不执行、任意 URL / 内网 / 跨域解析拒绝、在线鉴权、离线响应失效、并发和大小边界。
- `scripts/worker-check.ts` 经真实 workerd 与 Pages Service Binding 验证元数据路由、在线成员鉴权、MD5 / AES 公共响应值处理。上游在此项使用生成的元数据样片，不冒充实际网站可达；图片、聊天、休眠恢复和实时视频回归通过。
- 首次实际页面本地验收：从上述完整原站链接开始，约 8843 ms 获得结果；两个播放器实际解码 1920×1080 视频与音轨，暂停、5 秒进度和 1.25 倍速一致，取消 / 失败不替换当前媒体，无页面错误。该次 Node 路径使用既有 HTTP 视频代理，未重编码；之后将独立页面和配置读取改为并行以减少等待。
- 并行读取后的同链接本地复验：识别约 6777 ms，两端仍实际解码 1920×1080 与音轨，暂停、5 秒及 1.25 倍速一致，取消和错误回包未替换当前影片；证据在 `.local/mgn-playback-local-evidence.json`。最终格式、43 项测试、构建及 workerd 验证通过，包含慢请求输入取消后释放识别槽位、外部网络错误不暴露地址的检查。
- 先行正式页面实验确认原站签发的源可由两个浏览器直接解码 1920×1080，音频字节持续增长；仅识别配置或接口返回 200 没有作为可播放的充分证据。真实完整原站响应、源地址、凭据和视频字节不进入仓库。
- 首次部署后完整公开链接验收失败，定位到 Cloudflare 读取播放器配置返回 HTTP 520；没有据本地成功宣称正式服务可用。元数据请求补充明确的 VideoSreeeen User-Agent 与 Accept 后，正式入口完整验收通过：识别约 5616 ms，两端从 `r2.jzacg.com` 直接加载，均为 1920×1080，分别解码 229 / 239 帧，音轨字节均持续增长；暂停、5 秒进度及 1.25 倍速一致。没有使用屏幕捕获或原站 HTTP 视频代理，取消及错误响应保持当前影片，无页面错误。
- 上游 HTTP 错误显示读取阶段和状态码，不输出响应正文、视频地址或凭据；网络错误仍使用固定提示。workerd 验证同时检查真实出站请求携带应用标识。
- 部署后正式服务的实时画面回归通过：测试生成的 1280×720 视频与音轨约 6422 ms 开始播放，默认 4.5 Mbps；无法使用 WebRTC 时仍由正式 WSS 通道播放。进出成员不重启编码，提供方重连、清晰度切换、后加入、静音 / 全屏及停止清理均通过，页面错误为零。该项使用生成画面，没有捕获用户桌面或麦克风，证据在 `.local/broadcast-relay-evidence.json`。
- **可达性限制仍未消除**：完整播放验收通过之后重复调用正式接口，一次返回通用识别失败，另一次约 1745 ms 返回“房间服务读取原站播放页失败（HTTP 403）”。因此成功验收只说明可读取时的完整播放链路成立，不能宣称已保证 Cloudflare 每次都能读取原站。原站浏览器能播放与房间服务能读取是两个事实；不采用轮换身份、第三方代理或付费服务绕过拒绝。失败保留当前影片，识别有 12 秒截止时间，超时与主动取消使用明确提示。当前适配包含此限制。

测试入口为 `npm run test:mgn-playback`。`VS_PUBLIC_URL` 可切换到正式服务；本机网络分流必要时可设置仅用于验收浏览器的 `VS_TEST_PROXY`，不修改用户全局代理。
