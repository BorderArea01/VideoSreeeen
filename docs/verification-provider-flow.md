# 提供者本地预览修复与验收

2026-10-18。本轮已完成源码、构建和本地真实标签页共享验证；部署与公网验证结果将在完成后补充。

## 修复内容

- 标签页采集没有文件播放所用的 `publisher` 元素，旧预览分支因此跳过房主。现在单独持有采集流，直接绑定到房主播放器。
- 浏览器返回采集流后立即静音播放，不依赖观众、房间确认或旧页面的暂停状态。服务器确认前明确标为“本机预览”，不把预览称为观众已经收到。
- 服务端将标签页共享的初始状态设为播放；本地文件继续由房间播放控制。原站同步、客户端原站画面和共同缓存路径保留。
- 提交原站页面后提供两步操作流程；观看者默认等待画面，其他成员仍可接手提供。打开原站不会被标为已共享。
- 服务端记录页面提交者，忽略客户端伪造的身份字段。停止、换片、离房或发布失败释放采集；显示实际连接观众数与错误。
- 取消共享后重新打开原站，会清除上次取消提示。该问题由本轮首次浏览器验收发现并修正后重新构建。

## 已通过的验证

- `npm run verify`：格式检查、25 项单元与协议测试、TypeScript、前端及 Node 构建、Workers 类型检查和部署 dry-run；取消提示修正后又完成一次 `npm run build`。
- `test:browser-share` 使用真实 Edge 标签页采集，没有伪造视频流。只有房主且暂缓真实服务器确认时，预览为 1590×1062、解码 34 帧，64×36 像素采样中 2257 点非黑；目视截图为正常花朵视频。
- 恢复服务器确认后预览持续播放。随后观众加入，实际解码 15 帧并接收音频 RTP；停止后双方播放器清除、采集轨道结束。取消重试、无采集能力时的替代入口和手机布局通过，页面错误为 0。
- `test:onboarding`：建房、邀请、默认提供者步骤、重连、服务器设置、聊天与手机布局通过。
- `test:broadcast`：本地文件实际传输 960×540 音视频，暂停、拖动、后加入与停止清理通过。
- `test:worker`：真实 workerd 经 Pages Service Binding，验证 2,097,194 字节图片原图、休眠恢复、聊天与成员恢复，未启用视频中继。
- `test:p2p`：浏览器互传、同时下载、损坏块拒绝与源站回退、Windows 与浏览器双向分块传输、离房及结束清理通过。
- `test:ui` 已完成浏览器播放、完整缓存与清理，以及 Windows 原生磁盘缓存；进入后续原站探测时，可用内存降至 1520 MiB，资源守卫停止所属任务。因此不将本次整个 UI 检查记为通过，也未自动重启该任务。

本地证据：`.local/browser-share-evidence.json`、`.local/screenshots/provider-preview-before-ack.png`、`.local/screenshots/browser-tab-share.png`。这些运行记录未提交到仓库。

## 验证边界

用户确认原截图中观众刚离开；房主本地预览按其要求先独立验收，不以房间人数或观众操作为前提。点击播放不能解决原黑屏，未将它作为有效临时方案。

以上浏览器收发验证为同机不同页面，不代表不同网络之间的连通性。默认部署仅有 STUN，未自动添加付费 TURN。用户原站视频、不同网络接收与 Android 真机不因样片通过而被称为已验收；本轮未安装设备或重打客户端安装包。

## 资源规则

用户明确授权本轮游戏期间构建，保留 1536 MiB 内存门槛。所有本机编译、测试与部署经 `scripts/controlled.ps1` 串行执行，使用显式单次参数 `-AllowGameThisRun`；默认游戏检测、384 MiB Node 堆、持续内存检查与仅清理所属任务保持。先前被内存守卫停止的任务没有后台自动重启，本轮由用户明确要求重试。

GitHub Verify 云端调度曾返回 HTTP 422 `Actions has been disabled for this user`，没有云端构建结果；本页列出的成功结果来自本机受控任务。

## 实现依据

按 [MDN srcObject](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/srcObject) 将 `MediaStream` 直接绑定到播放器；按 [getDisplayMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia) 保留点击触发的用户授权与真实采集。
