## 对照 ZNote 的实际实现

只读检查 `D:/Workspace/ZNote`，未修改其代码、数据、扩展设置或服务器：

- 扩展具有相应主机权限；这种能力和普通第三方网页的跨域权限不同。不能因为纯网页直接读取登录态受限，就推断合法取得的媒体流不能交给网页播放。参见 [Chrome 扩展网络请求文档](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)。

## 取得与实播流程

在用户已经打开的 ZNote 扩展页面上下文中执行受限诊断，复用浏览器正常的凭据处理。先请求官方 `/x/web-interface/nav`，只读取 `data.isLogin` 布尔值，实测为 `true`。再以用户指定 BV 请求官方 `/x/web-interface/view` 获取匹配 CID。没有读取账号标识、Cookie、令牌或浏览器配置文件。

对同一 BV / CID，正常 `credentials: 'include'` 请求 `/x/player/playurl`：

| 路径                          | 返回信息                                                                        | 实际网页解码                                |
| ----------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------- |
| HTML5，`qn=80&platform=html5` | quality 64，`mp4720`，完整 862 秒，无预览 / DRM 标记                            | 1280×720，独立网页实际音频与持续出帧        |
| DASH，`qn=80&fnval=16`        | quality 80，AVC `avc1.640032` / AAC `mp4a.40.2`，完整 862 秒，无预览 / DRM 标记 | 两端 1920×1080，实际 AAC 解码字节与持续出帧 |

DASH 返回的顶层 `format` 字段在本次响应中为 `flv`，实际使用的是 `data.dash` 中的 AVC / AAC 轨道；没有根据顶层字符串或菜单名称猜测解码格式、画质。视频使用原站签发的 `*.mcdn.bilivideo.cn` 地址，音轨使用原站返回地址，未修改签名参数或强行改成其他 CDN。

选中这些正常返回的轨道后，只把视频源和音轨地址交给测试房间，账号凭据仍由原浏览器管理。两位观众使用新的隔离浏览器上下文，未使用提供方的账号会话。既有服务器媒体操作协议完成状态发布、暂停与拖动裁决；没有增加第二个房间状态写入者。

1080p 房间验收中，两端分别取得约 205 / 195 帧、68,865 / 69,662 个音频解码字节，播放中拖动后继续出帧，随后双方暂停成功。测试音频输出保持静音；这些统计不能代替扬声器听感验收。该次检查是短时同机双浏览器使用真实公网服务，不是两地网络与长片验收。
