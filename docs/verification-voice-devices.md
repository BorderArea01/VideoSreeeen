# 房间语音设备选择

2026-10-21。用户指出首版仅使用系统默认输入与输出，缺少设备选择。本轮扩展现有语音客户端，不改房间控制、编解码协议、视频输出或免费服务配置。

## 交互与恢复

- 侧栏“房间语音 → 音频设备”分列输入麦克风、输出扬声器 / 耳机，保留系统默认项与刷新按钮。设备名称作为文本显示。刷新列表不调用 getUserMedia，不会暗中开麦；首次主动开麦授权后再次枚举。未获权限的列表可能不完整，不能展示虚构的设备。
- 输入使用 getUserMedia 的 `deviceId.exact`。不开麦时只保存选择；开麦期间先取得新流、确认仍属于当前会话，再替换输入节点并停止旧轨道，保留原有编码器、序号和语音连接。失败保留原设备。切换尚未完成时仍可关麦或退出，迟到的新流立即停止。
- 输出通过真实语音 AudioContext 的 `setSinkId` 路由，独立于视频播放器。支持 `selectAudioOutput` 时，下拉项“选择其他输出设备…”在用户手势内唤起浏览器选择；不借此申请麦克风。不支持当前输出 API 的浏览器禁用输出下拉框并说明跟随系统；不以一个无效的选择框冒充可用。
- 输入 / 输出偏好只保存在本机 localStorage，不上传房间服务，不记录真实设备标识或名称到诊断。保存过的输出会在再次加入时应用；已失效或未获授权时改为默认并静音，提示重新选择。
- 输出切换串行执行，使用请求与会话校验；退出后完成的旧请求不能修改新会话或保存偏好。输出被移除时先在本机静音，再退回默认，避免突然从扬声器放声。输入被移除时停止开麦，重选后需主动再次开麦。监听 devicechange，显式刷新也可更新列表。
- 设备只影响房间语音；不向其他成员发布媒体、暂停、拖动或缓存命令。不保存录音，不开摄像头，不变更系统全局输入、输出或音量。

## 自动验证与真机边界

在已有 `test:voice` 中扩展独立浏览器验收，继续通过合成音源和静音的物理输出执行，**不访问用户真实麦克风、不切换用户物理扬声器、不录音**：

- 麦克风 A / B 是隔离上下文的 API 测试设备，不是产品内模拟在线成员或硬件。切换后另一端的实际解码和混音输出出现新音源的频率，旧轨道已停止；拒绝新输入时保留旧流。
- 设备列表刷新不增加麦克风请求数；输出选择、拒绝输出、设备移除、切换中关麦及退出后的迟到结果均有验证。移除输入后清理轨道；移除输出后本机增益为零。
- 输出非默认 ID 和浏览器选择器使用 API 边界桩，不伪称物理耳机路由已验证。桩内部调用浏览器原生 `AudioContext.setSinkId('')`，验证默认路由与原有混音图继续工作；特定耳机、扬声器和蓝牙实际切换仍需真机确认。
- 删除该输出 API 的独立浏览器上下文仍能收发语音，输出选择禁用，提示跟随系统。保存输出重入恢复、保存输出失败后默认静音、退出时待完成的输出切换不写回偏好均纳入验收。
- 原有双向 Opus、三人同时语音、180 ms 抖动、兼容协商、重连收听、麦克风拒绝与权限迟到清理继续检查，期间视频持续解码，语音操作不发送房间播放控制。

未安装新 APK 或 Windows 安装包；手机平台、系统设备授权、蓝牙配置和真实回声没有被桌面 API 桩或移动视口冒充验收。不同浏览器的输出选择支持范围有差异，不能承诺所有手机都能在网页里切换听筒 / 扬声器。

参考了 [Web Audio 1.1 setSinkId 草案](https://webaudio.github.io/web-audio-api/#dom-audiocontext-setsinkid)、[设备选择规范](https://w3c.github.io/mediacapture-output/) 与 [WebRTC 官方设备选择示例](https://github.com/webrtc/samples/tree/gh-pages/src/content/devices/input-output)。未复制第三方实现或增加音频依赖。
