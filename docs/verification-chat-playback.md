# 0.4.3 聊天、恢复和下一集验证

## 范围与状态所有者

聊天室大小与滚动属于本机界面；剪贴板图片复用已鉴权的独立 HTTP 附件通道，不向房间 WebSocket 塞入原图。浏览器只在用户粘贴事件中读取提供的图片，不轮询系统剪贴板。普通文字粘贴、现有草稿、Emoji、图片查看与弹幕保留。

播放状态仍由房间服务独占。播放中的本机缓冲不能触发无限重复跳转，显式新拖动可以覆盖旧目标。显式 seek 等播放器实际可接受时才消费其版本。音轨在跳转中不重复寻址；有可播数据却不出帧时本机尝试一次暂停/播放恢复，后续实际出帧才重新开始观察。后台标签页、正常下载中的空缓冲、seek 中和结束状态不会反复触发恢复。HLS 致命网络/媒体错误最多恢复两次，仍失败显示真实错误。

“下一集”只接受原站明确给出的同番、同线路地址，不推算 ID。识别失败、末集与迟到结果保留当前媒体；切换使用既有版本冲突与操作去重。播放中切集待提供者首帧就绪再发送房间 play；暂停时切集不自动播放。B 站只适配同 BV 分 P。客户端从其本机原站页面读取公开剧集信息，不读取或上传 Cookie。网页版元数据服务限定站点、路径、身份、请求大小和期限，仍关闭原站视频代理。

## 已完成的本地验证

- `npm run verify`：61 项单元测试、前后端构建、Worker 类型与 dry-run 通过。
- 聊天双浏览器：24 条消息后面板高度不变，历史上翻后新消息不拉回底部；粘贴 1,484,296 字节的自建 PNG，双方实际解码为 768×768，草稿保留。缓存子入口、弹幕、RTT 同步和过期验证保留。
- 真实喜番 `151/play/1986?source=xfy2`：独立浏览器双方实际 1920×1080 解码及音频；播放中跳到 30 秒继续出帧。通过 CDP 仅让观众网络断开 3.5 秒，同时跳转到 300 秒，恢复网络后无需房间暂停/播放即继续出帧。
- 同一喜番页面的“下一集”实际读取 `1987?source=xfy2`，两端新视频首帧就绪且从开头继续播放；失败和取消不能替换当前视频。
- 本地文件 WebSocket 共享的播放中拖动、暂停、倍速、晚加入、停止清理回归通过。
- Windows 两个隔离原站客户端：蜜柑 `193-3-17` 实际 1080p 和音频解码；播放、暂停、5 秒、1.25 倍速稳定；原站内拖动至 8 秒同步到房间。下一集实际切到 `193-3-18`，两端从开头出帧（19/24 帧）。首次回归暴露原站操作采样迟到后回传纠偏位置的问题；改为在事件发生时保留操作位置/倍速后重测通过。

本轮针对的观众原始卡死没有稳定复现；网络中断恢复用例与本机恢复判定测试不能冒充已定位该现场的唯一根因。Android 仅打包，不安装或操控设备；Safari/iOS 不在本机验收范围内。

浏览器粘贴依据：[ClipboardEvent.clipboardData](https://developer.mozilla.org/en-US/docs/Web/API/ClipboardEvent/clipboardData)。HLS 加载接口依据：[Hls.startLoad](https://hlsjs.video-dev.org/api-docs/hls.js.hls.startload)。
