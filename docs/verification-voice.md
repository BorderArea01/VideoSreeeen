# 房间语音：实现与验证

2026-10-21。语音默认关闭；加入只收听，用户主动点“开麦”才调用麦克风权限。当前交付先更新网页和 Node / Cloudflare 服务，未发布新 Windows 安装包或 Android APK。旧安装包不因网页部署自动获得新入口。手机和 Windows 可先用 HTTPS 网页，苹果设备继续走浏览器。

## 通道和资源边界

`麦克风 → 本机编码 → /voice WebSocket → 同房间语音成员 → 各自解码、缓冲、混音`。

- 沿用一个房间一个 SQLite Durable Object；Pages 通过原有 WATCH Service Binding 到同一 Worker。Node 自建也支持。不新建收费服务，不使用 TURN，不把音频塞进聊天或房间控制 WebSocket。
- 每个开麦成员只上传一份音频，服务器按真实语音成员转发，最多 8 人。不同接收者的积压与 ACK 窗口分开计算；慢接收者断开重连不等待全员。房间连接总上限从 24 增为 32，为独立语音预留最多 8 条连接，不改变 16 个房间成员上限。
- 双端原生 WebCodecs 能力通过时使用 Opus：48 kHz 单声道、24 kbit/s、20 ms 帧。任一语音成员不支持时，全体改为自有 `mulaw16` 兼容格式：16 kHz 单声道、对数压扩、约 128 kbit/s，播放时插值到 48 kHz；不冒称为标准 G.711，也不冒称兼容格式与 Opus 音质相同。成员退出后重新协商。
- 每包最多 4 帧（80 ms），降低消息频率；没有自行加入噪声门限来切掉轻声、词头或尾音。申请浏览器回声消除、降噪和增益控制，其实际效果由浏览器、设备及耳机决定。
- 兼容成员加入或退出引起编码切换时会重建解码与缓冲队列，可能出现短暂声音间隔；这版不承诺切换时无缝。
- 每位说话者各自使用有界抖动队列，初始目标 120 ms，根据到达抖动提高至最多 400 ms；小幅调整消费速度应对时钟漂移。短缺时保留期望序号、等待原样本；严重积压或长中断会重置到近期音频。队列最多约 1 秒，不无限回放旧讲话。目标缓冲不是实际端到端通话延迟，后者还包括采集、编码、80 ms 分包和网络时间。
- 捕获端 MessagePort 最多积压 12 帧；编码队列、解码队列、WebSocket bufferedAmount、服务器接收速率和每个观众确认窗口均有上限。过载或连接重建停止麦克风，恢复后先收听，由用户再次开麦，不能把“重连”显示成持续完整通话。
- 房间身份逐次校验，服务端添加发送者身份，拒绝伪造身份、重复序号、超限包和未开麦推送；声音仅转发给同房间的在线语音成员。语音成员变化不增加播放版本、不暂停、不拖动、不改共同缓存代次。
- 退出、离开房间、页面销毁、主房间连接中断均清理轨道和音频上下文；迟到的权限结果立即停止。浏览器暂停音频上下文时停止开麦并提示恢复声音。用户单人静音、总接收静音和语音音量只影响本机。
- 音频不写 SQLite、文件或历史；Durable Object 休眠恢复会关闭旧语音 socket，客户端重新认证、重新建缓冲，不重放旧音频。WebSocket 传输通过 HTTPS/WSS 加密，**不是端到端加密**；服务端能够处理音频载荷，界面说明这一点。

## 零付费的适用范围

继续使用现有免费计划，未启用付费 TURN、SFU 或按量计费升级。免费并不等于无限通话：语音上行、ACK、心跳会消耗现有服务额度，并与视频转发、房间操作共享资源。关闭麦克风可停止持续上行。

Cloudflare 当前文档列出免费 Durable Objects 请求 100,000 / 日、时长 13,000 GB-s / 日，入站 WebSocket 消息按 20:1 折算请求，出站消息不计请求费；免费限制耗尽会失败，不会由本项目自动升级。仅计算连续开麦音频，80 ms 一包约 2,250 个折算请求 / 人时，尚未包括 ACK、房间心跳等。8 人持续开麦数小时可能耗尽共享日额度，不能宣传为公开无限语音服务。依据：[Durable Objects 官方额度与计算方式](https://developers.cloudflare.com/durable-objects/platform/pricing/)。

TCP 能重传短时丢包，但重传也可能增加延迟；无法承诺严重丢包、限速、锁屏或系统挂起时不吞音。这版不是成熟商业语音服务的等价替代，也没有宣称启用了无法通过当前解码 API 验证的 Opus FEC。

## 可重复验收

- `npm run verify`：协议、鉴权、重放、上限、慢接收者隔离、PCM 音质误差、短缺等待与长积压边界，加上已有播放、缓存、聊天测试及构建。
- `npm run test:voice`：隔离 Edge 浏览器上下文，**只使用合成音源，物理声音输出静音，不访问用户真实麦克风、不录音**。双向 Opus 实际解码、单端 180 ms 到达抖动、三人同时讲话与兼容协商、实际混音频谱、单人接收静音、退出和迟到权限清理、断线后先收听。检查语音全过程没有房间播放控制指令。
- `npm run test:worker`：真实 workerd，经 Pages Service Binding 验证语音认证与二进制转发；主动休眠后关闭旧语音连接，再建新会话，原房间聊天和成员恢复仍通过。
- `VS_PUBLIC_URL=https://videosreeeen.pages.dev npm run test:voice`：同一套合成音源走线上真实 WSS；代理可用 `VS_TEST_PROXY` 显式提供，不写死个人代理配置。

测试不会以合成正弦波冒充人声主观听感，也不会以桌面浏览器代替 Android / iPhone 真机结论。真实设备麦克风、扬声器回声、蓝牙切换、移动网络、锁屏及多人自然对话尚需现场验收。Android 旧 APK 未包含语音权限处理，这次不声称 APK 开麦已可用；网页可用性也需以目标手机实际结果为准。

编码依据：[W3C WebCodecs Opus 注册规范](https://www.w3.org/TR/webcodecs-opus-codec-registration/)、[Xiph Opus](https://github.com/xiph/opus)。实现没有复制第三方音频代码或新增音频依赖。

## 本轮实际结果与部署

- `npm run verify` 通过：80 项单元测试、格式检查、TypeScript、前端 / Node 构建、Worker 类型检查及 dry-run。随后补强的跨房间鉴权断言也重新通过语音单元测试。
- `test:worker` 通过，包括已有图片、聊天、房间恢复和画面转发回归；新的语音转发及休眠后新会话通过。
- `test:voice` 本地和正式 Pages 地址均通过。两人 Opus 实际双向解码；三人同时提供音频、兼容编码切换、麦克风拒绝后继续收听、单人静音、断线后收听、迟到权限清理均通过。
- 线上 180 ms 到达抖动阶段，健康端无欠载，受影响端出现 1 次欠载等待、0 次跳帧重置；随后解码继续，取样时队列为 340 ms。测试未宣称全过程零停顿或真实人声不吞字。
- 三人同时通话时，视频分别已解码 315 / 312 / 312 帧，均在播放，进度 12.930 / 12.794 / 12.804 秒；语音操作发出的房间播放控制指令为 0。实际混音输出的两个测试频率峰值约 -30.53 / -30.33 dB。物理输出静音，未调用真实麦克风，未保存音频样本。
