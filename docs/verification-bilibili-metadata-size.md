# 2026-11-01 B 站大合集响应大小修复

用户链接为 `https://www.bilibili.com/video/BV1eYxy6UEMj/`，房主助手报“B 站响应超过大小限制”。错误来自扩展元数据读取器，不是视频文件过大或缓存容量不足。

## 现场响应与原因

只读请求该 BV 的正常公开 `/x/web-interface/view` 接口，HTTP 200、业务码 0。响应实际为 683,580 字节（约 668 KiB），共 1 个分 P，附带 366 集的 UGC 合集目录；其中 `ugc_season` 单字段为 681,258 字节。原来的所有接口统一 512 KiB 上限，在解析 BV 元数据之前就阻止了这个合法响应。没有保存原始接口响应、登录凭据或视频文件，回执只保留字节统计与状态。

## 实现

- `extension/metadata.ts` 按固定只读接口分别限额：登录状态 64 KiB、视频信息 8 MiB、播放信息 512 KiB。只扩大需要容纳完整合集目录的视频信息接口，不改变登录与播放签发流程。
- 流式 UTF-8 解码，正确保留跨块的中文和 Emoji；声明超限可提前拒绝，读取过程中始终按实际响应字节检查，缺失 / 谎报长度不能绕过限制。超限、取消、超时和失败均关闭读取流、释放锁。没有取消大小限制。
- 请求仍由浏览器正常会话处理，仅接受固定白名单的三个 B 站元数据接口；权限没有扩大，不读取、导出或上传 Cookie。合集目录留在扩展本机，放映厅只收到已校验的紧凑影片和轨道信息。
- 助手版本 0.1.2，网页识别旧助手并提示更新。加载原解压目录的房主需在扩展管理页重新加载；安装在别处的房主需下载新 ZIP、覆盖原目录后重新加载。观众不要求助手。网页发布不会替代已安装浏览器扩展的代码。
- 继续使用正常登录后的 HTML5 720p / 1080p AVC 与 AAC，保留原始 CDN 签名和现有访问权限检查。不恢复游客低画质、服务端扫码或视频代理。

采用既有扩展后台受限取源架构，参考 [Chrome 扩展跨域请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests) 与 [Fetch Standard 响应体](https://fetch.spec.whatwg.org/#concept-response-body)，没有新增依赖。
