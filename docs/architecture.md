# VideoSreeeen 架构与交付边界

目标：Windows 独立客户端、Android APK、苹果等设备的浏览器入口。GPL-3.0-only。

## 状态所有权

- 服务端是房间、成员、播放时间线、媒体版本、缓存代次和聊天顺序的唯一写入者。
- 客户端发送显式操作，带当前版本与唯一操作 ID；服务端串行接受第一条有效操作，过期操作返回冲突和最新快照，禁止静默覆盖。
- 播放器自动跟随不产生新操作。小误差忽略、中误差调速、大误差跳转；主动拖动直接对齐。
- 成员延迟是客户端到房间服务器的往返时间，不是成员之间的点对点延迟。未测得时显示未知。

## 原站与播放源

Windows 使用隔离的 Electron WebContentsView，Android 使用独立 WebView；原站不获得文件、房间令牌或应用桥接权限。客户端轮询播放器状态与提取可访问媒体；普通播放可使用原站播放器。Bilibili、喜番和蜜柑为优先适配入口，iframe 也需要采样。页面改版、验证码、登录和分片源均可能阻断；以真实验证记录为准。

浏览器无法向第三方网页注入控制脚本。苹果端通过房间内置播放器播放已经共享的直连源或客户端提取后共享的媒体源；不能把 iframe 展示当作完成第三方播放器同步。

0.3.1 的客户端在当前媒体仍缺少源时自动提交一次识别结果，沿用普通媒体操作的版本裁决；不绕过服务端写房间状态，冲突后保留手动重试。首次给同一页面补充源时保留服务端当前时间线，媒体 ID / 缓存代次仍更新以隔离旧数据。原生客户端保留原站视图，避免因共享源而切换到可能遭源站拒绝的直接播放器；换页面、缓存模式和退出仍关闭旧视图。异步采样校验媒体 ID，过期结果不得写入新视频。

B 站音视频优先选择原站实际返回的普通 HTTPS 端口备源及 AVC/AAC 轨道，不拼接、伪造签名地址。浏览器在缺少源时明确显示等待客户端；音视频加载失败时显示提供方共享画面或重新识别的入口，共同缓存保留为折叠的手动选择，不显示“已共享”暗示可以播放。切换缓存时，在原站视图关闭与旧缓存清理完成前禁用下载按钮，防止点击被尚未关闭的原生视图吞掉。公开部署仍不转发视频。

## 可选实时画面与文件播放

链接同步、原站画面共享、本地文件共享并存。每个实时媒体包含服务端确认的 host、媒体 ID 与 epoch；成员不能冒用他人身份提供画面。信令标记 broadcast，与 cache 信令分离，只允许提供者和接收者之间交换。每位接收者一条连接，目标最高 1080p / 30fps、单连接视频上限 6 Mbps，保留分辨率并根据网络调整帧率及码率；提供者上行带宽随接收人数增长。

Windows 仅在主界面显式点击后，对隔离原站 WebContentsView 的 WebFrameMain 授予一次采集，不采集整个桌面或麦克风；原站仍没有特权桥接。桌面浏览器使用系统标签页选择器。本地文件从用户选择的 File / Blob URL 解码，优先 captureStream，不支持时用有尺寸上限的 Canvas 与 Web Audio；不将整个文件读入内存或传到房间服务器。

远端 MediaStream 不做时间线跳转或调速纠偏。控制仍按房间版本裁决，并驱动提供方的原站或文件播放器；接收端保持实时播放。屏幕共享只提供播放/暂停，进度与速度由提供方原播放器调整。提供者离线会暂停房间，重新入房重新协商；停止、换片、离房会释放连接、轨道及应用创建的 Blob URL，不删除用户源文件。

聊天图片通过 HTTP 二进制附件发送，最大 20 MiB，服务端验证文件头及成员恢复凭证。Node 存到本实例专用临时目录，Durable Object 用 64 KiB 分块存储；快照只包含引用。下载用随机附件 ID，禁止脚本类型，附带 nosniff / sandbox / no-store；随消息滚动或房间过期回收。

## 共同缓存

每人完整保存同一媒体的全部文件/有限 HLS 分片到自己的设备。0.2 的 MP4 / DASH 路径通过房间内 WebRTC DataChannel 互传已验证的 256 KiB 块，传输帧 12 KiB，限制排队和缓冲；缓存进度分别统计成员与源站字节数。成员按当前下载者排序选择不同的优先块，未获得的块在超时后回退源站。HLS 保留完整下载路径，尚不互传。

缓存进度带 mediaId 与 epoch；仅全部在线成员完成且内容指纹一致才允许播放。新成员加入、断线、换片和失败均关闭就绪门槛。直播、加密 HLS、不可完整获取的源明确拒绝。房间 WebSocket 仅传状态与定向信令，视频文件经独立数据通道传输。对端声明的块哈希验证传输一致性；最终全文件与整部内容指纹仍须重新计算，不能把对端声明当作源站签名。

结束由每位成员的播放器确认（同时接近媒体末尾）后统一触发清理；退出、换片也清理。删除只针对应用创建的缓存目录；崩溃后下次启动清扫过期缓存。下载流式落盘，有上限、取消和失败回滚，不能整片读入内存。浏览器受存储配额、后台生命周期和 CORS 限制。

## 入房与设置的边界

默认流程为“昵称 → 创建房间 → 自动展示邀请”，接收者打开链接后直接进入加入页。邀请码由服务端生成，六位房间号不能代替入房凭证。创建与加入分开呈现，不要求普通使用者理解服务器或自行设置密码。

默认服务器来自网页自身 origin 或原生构建中的公开配置；用户可在折叠的高级设置中保存自建地址。完整邀请携带服务器，优先连接邀请中的 origin，但不写回用户默认配置。浏览器地址栏中的邀请同样保留自身 origin，避免已保存的自建地址将深链接导向错误服务器。当前会话另行持有实际服务器与昵称，修改下次连接设置不能改变重连目标或生成的邀请。

创建/加入时禁用重复提交，显示进行状态；失败在原表单说明原因并恢复重试。复制失败时展示并选中可手动复制的邀请，不能退回创建表单。系统分享只由分享按钮直接触发，取消分享不提示故障；不支持时保留复制方式。依据 [Web Share API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Share_API) 的安全上下文和用户手势要求实现，不在异步建房完成后自动弹系统分享。

应用内设置提供初次使用、端能力和反馈入口；仓库 README 先列直接使用步骤，再给开发与自部署命令。客户端由 GitHub Releases 分发，Windows 使用 NSIS / electron-updater，Android 校验哈希、包名、签名后交给系统安装；细节见 updates.md。

## 连接失败与恢复

断线期间禁止发送控制，重连用成员恢复令牌重新入房并接收完整快照。Node 自建后端仍使用内存房间，进程重启后邀请失效。Cloudflare 后端每房间一个 SQLite Durable Object，房间关键状态与有限聊天持久化；休眠连接的附件绑定成员，唤醒时恢复在线连接和状态，缺失的连接必须关闭缓存门槛。客户端重连重新确认完整缓存，不沿用历史 ready。任务失败显示真实错误且不自动重试。聊天和图片限制大小、数量与总字节数。

Workers 静态资源提供同域网页；Workers 路由到房间对象，不代理视频。Native 可直接下载并向浏览器分享；浏览器直连仍受源站 CORS 和配额限制。默认 STUN，未配置 TURN；P2P 直连失败时回退下载，不自动购买中继。旧 Node 服务保留视频代理，两个部署模式通过 `/config` 明确区分。详见 cloudflare.md。
